     结论

     1. 投机接受率显著提升: 24.5% → 31.6% (+7.1pp)，EARS 的自适应容忍机制有效减少了"随机性误杀"
     2. 吞吐量提升约 10%: Output Throughput 从 27.57 提升到 30.30 tok/s
     3. TPOT 降低 8.3%: 每 token 处理时间从 36.39ms 降到 33.36ms
     4. 每次迭代解码 token 数增加: 1.32 → 1.46 (+10.6%)，说明每次验证能接受更多草稿 token

     注意：Avg Latency 增加是因为 EARS 生成了更多输出 token（1589 vs 1370），如果按单位 token 延迟计算，EARS 实际更快。

     与论文数据对比: 论文报告 +18.12% throughput，本次实测 +9.9%。差异可能来自硬件不同（论文用 Ascend NPU，本次用 NVIDIA L20）或测试样本差异。

     关键发现

     1. 长文本场景效果更明显：2048 token 输出（vs 之前 openqa 的 ~1500），EARS 提升从 +9.9% 增长到 *+11.0%*。长文本意味着更多高熵生成步骤，EARS 的赦免机制有更多发挥空间。

     2. *TPOT 降低 7.3%*（30.99 → 28.73ms）：被接受的 token 更多，减少了"拒绝后重新生成"的开销。

     3. draft 数量减少 8%（50215 → 46200），但接受的 token 更多（10444 → 11246）：EARS 每次投机轮次的有效产出更高，达到同样输出量需要的轮次更少。

     4. 每位置接受率全面提升，尤其是 Position 0 从 48.69% 提升到 55.09%（+6.4pp），说明 EARS 对早期 token 的赦免效果最显著。

     结论：EARS 在长文本（2048 tokens）、temperature=0.9 的场景下，吞吐提升 *+11%*，投机接受率从 20.8% 提升到 24.3%（+17% 相对提升），表现优于短文本测试。
